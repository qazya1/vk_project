# VkPublications

Десктоп-приложение на C++/Qt5 для автоматизации публикации вакансий в
сообществах ВКонтакте: импорт вакансий из XML-выгрузок 1С/HR-систем,
плановая публикация и репост по расписанию с гибкими правилами
форматирования текста, ведение нескольких групп ВК одновременно и полная
история публикаций в локальной базе данных.

Проект разработан как индивидуальный заказ для HR-агентства/кадрового
агрегатора и выкладывается в открытый доступ как элемент портфолио —
исходники подготовлены к публикации (проверены на отсутствие токенов,
персональных данных и локальных путей заказчика).

## Возможности

**Импорт и хранение вакансий**
- Импорт объявлений из XML-выгрузок (парсинг через pugixml) с защитой от
  дублей: SQL-триггеры на стороне SQLite не дают добавить вакансию с уже
  истёкшим сроком публикации или клон объявления по более старому счёту.
- Таблица объявлений с постраничной навигацией, сортировкой по колонкам,
  построчными и полнотекстовыми фильтрами, инлайн-редактированием ячеек.
- Экспорт выборки в `.xlsx` (через встроенную QXlsx) с сохранением
  форматирования заголовков.

**Публикация в ВКонтакте**
- Гибкие настройки на группу: интервал между постами, окно публикации по
  времени или круглосуточно, авто-репост с заданным интервалом,
  объединение нескольких вакансий в один пост (по вакансии/по номеру
  счёта/по периоду), скрытие названий компаний/адреса/доп. информации,
  замена маленькой зарплаты на «по договорённости».
- Публикация, репост и удаление постов выполняются в отдельном
  Python-процессе (`publicate.py`) через `QProcess`, что не блокирует UI и
  позволяет останавливать/перезапускать публикацию независимо для каждой
  группы.
- Отдельный воркер (`clear_wall.py`) для полной очистки стены сообщества.
- Фоновые задачи (публикация/очистка) переживают перезапуск приложения —
  их состояние хранится в БД и восстанавливается при старте.

**Управление сообществами**
- Авторизация ВК через OAuth 2.0 + PKCE с локальным HTTP-сервером для
  приёма редиректа — токен и device_id заводятся прямо в приложении, без
  ручного копирования кода авторизации.
- Одновременная работа с произвольным числом групп, у каждой — свой набор
  токенов, свой файл-фильтр разрешённых вакансий и независимый статус
  публикации.

## Архитектура

Приложение построено слоями, чтобы бизнес-логика не была завязана на
виджеты Qt:

```
UI (Widgets, .ui)
   │
   ▼
*TabController  — реакция на события UI, оркестрация сервисов
   │                 (AnnouncementsTabController, GroupsTabController,
   │                  XmlImportTabController)
   ▼
*Service         — бизнес-логика, не знает о Qt Widgets
   │                 (AnnouncementService, GroupService, XmlImportService,
   │                  BackgroundJobService)
   ▼
DatabaseManager / GroupRepository  — доступ к SQLite
   │
   ▼
SQLite (+ кастомная функция LIKE_NOCASE через C API sqlite3)
```

Публикация и очистка стены вынесены из основного процесса в отдельные
Python-скрипты (`PublishProcessManager` запускает и отслеживает их через
`QProcess`) — это изолирует обращения к VK API и долгие операции от UI-потока.

## Стек технологий

| Слой               | Технологии                                                        |
|--------------------|--------------------------------------------------------------------|
| UI / приложение    | C++11, Qt5 (Widgets, Sql, Network), qmake                          |
| База данных        | SQLite (через `QSqlDatabase` + прямой C API для кастомных функций) |
| Экспорт в Excel     | [QXlsx](https://github.com/QtExcel/QXlsx)                          |
| Разбор XML          | [pugixml](https://github.com/zeux/pugixml)                        |
| Авторизация ВК      | OAuth 2.0 + PKCE, локальный `QTcpServer` для редиректа             |
| Публикация в VK API | Python 3, `vk_api`, `requests`, `pandas`                           |
| Межпроцессное взаимодействие | `QProcess` (публикация и очистка стены — отдельные процессы) |

## Структура проекта

```
├── mainwindow.*                 точка входа UI, сборка сервисов и вкладок
├── announcementstab*.{h,cpp}    вкладка «Объявления»: таблица, фильтры, экспорт
├── announcementtable*.{h,cpp}   модель/форматирование таблицы объявлений
├── groupstabcontroller.*        вкладка «Группы»: CRUD групп, запуск публикации
├── groupwidget.*                карточка одной группы с настройками публикации
├── xmlimport*.{h,cpp}           вкладка импорта XML + сервис парсинга
├── databasemanager.*            схема БД, миграции, CRUD-запросы к SQLite
├── grouprepository.*, group.*   доменная модель группы ВК
├── vkoauth2.*                   OAuth 2.0 + PKCE авторизация ВК
├── publishprocessmanager.*      запуск/остановка Python-воркеров публикации
├── backgroundjobservice.*       персистентное состояние фоновых задач
├── QXlsx/, pugixml/, sqlite/    вендоренные сторонние библиотеки (исходники)
├── publicate.py                 воркер публикации/репоста в VK API
├── clear_wall.py                воркер полной очистки стены сообщества
└── resources/                   иконки, шрифты, .qrc
```

## Сборка

### Зависимости

- Qt5 (Widgets, Sql, Network) + qmake
- Приватные заголовки Qt5 (нужны встроенной библиотеке QXlsx):
  Ubuntu/Debian — пакет `qtbase5-private-dev`
- Компилятор C++11
- Драйвер SQLite для Qt (`libqt5sql5-sqlite` в Ubuntu/Debian)

```bash
sudo apt-get install qtbase5-dev qt5-qmake qtbase5-dev-tools \
    qtbase5-private-dev libqt5sql5-sqlite build-essential
```

### Компиляция

```bash
qmake VkPublications.pro
make -j"$(nproc)"
```

Сторонние библиотеки подключены исходным кодом прямо в репозитории (не
git-сабмодулями), поэтому отдельно устанавливать их не нужно:

- `QXlsx/` — экспорт в Excel ([QtExcel/QXlsx](https://github.com/QtExcel/QXlsx), MIT)
- `pugixml/` — разбор XML ([zeux/pugixml](https://github.com/zeux/pugixml), MIT)
- `sqlite/` — амальгамация SQLite ([azadkuh/sqlite-amalgamation](https://github.com/azadkuh/sqlite-amalgamation), public domain) —
  нужна, чтобы приложение могло регистрировать собственную SQL-функцию
  (`LIKE_NOCASE`) через C API sqlite3 поверх соединения, открытого драйвером Qt.

### Воркеры публикации

`publicate.py` и `clear_wall.py` запускаются приложением как
`./publicate/publicate.exe` и `./clear_wall/clear_wall.exe` рядом с
исполняемым файлом — их нужно собрать отдельно (например, PyInstaller) и
положить в соответствующие подпапки. Зависимости скриптов: `vk_api`,
`requests`, `pandas`.

## Известные ограничения

- Однопользовательское десктоп-приложение: хранит все токены и БД локально,
  без облачной синхронизации.
- Python-воркеры публикации распространяются как исходники — сборка
  исполняемых файлов под целевую ОС на стороне пользователя.
